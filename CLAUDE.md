# Lingua — контекст проекта для Claude Code

Онлайн-платформа изучения английского: точная диагностика уровня по 5 навыкам →
персональный план → уроки → самостоятельная работа → проверка куратором →
отчёт родителю → прогресс → новый план. Полное описание продукта: `BRIEF.md`.
Порядок работ и текущий шаг: `ROADMAP.md`.

## Кто со мной работает

Владелец проекта делает его один и не является опытным разработчиком. Поэтому:

- объясняй простыми словами, что делаешь и зачем; термины поясняй при первом упоминании;
- перед большой задачей коротко покажи план и дождись подтверждения;
- если нужно что-то установить, зарегистрировать или нажать самому, давай пошаговую инструкцию;
- после каждой законченной части скажи, **как проверить это в браузере**, и сделай git-коммит;
- не начинай следующий шаг ROADMAP без просьбы; после завершения шага отметь его в ROADMAP.md;
- если чего-то не знаешь о продукте (цены, тексты, правила), спроси, а не придумывай.

## Устройство API (уже сделано на этапе 1)

- `src/db/schema.ts` — вся схема БД. Изменение: схема → `db:generate` → `db:migrate`. Сгенерированные миграции не редактировать вручную, кроме добавления того, что Drizzle не умеет.
- Глобальные guards: `ThrottlerGuard` → `JwtAuthGuard` → `RolesGuard`.
  - `@Public()` — без токена; `@Roles('CURATOR', ...)` — по ролям;
  - `@AllowPending()` — доступно несовершеннолетнему, который ждёт согласия родителя (по умолчанию закрыто).
- `AccessService.assertCanViewStudent(actor, studentId)` — **единственный** способ проверить доступ к данным ученика: ученик — себя, родитель — привязанных детей, куратор — назначенных учеников, админ — всех. Чужое → 404.
- `AuditService.log()` — журнал важных действий.
- `ConsentsService` — согласия с версиями: `DATA_PROCESSING`, `VOICE_RECORDING`, `CAMERA`, `MICROPHONE`, `MARKETING`.
- Модули: `auth`, `users`, `consents`, `family` (ученик/родитель), `admin`, `curator`, `health`.

## Обязательные правила

**Доступ и приватность**
1. Любой эндпоинт, отдающий данные ученика (прогресс, ответы, ДЗ, записи, отчёты), вызывает `AccessService`. Роли недостаточно.
2. Записи голоса и камеры: только при действующем согласии (`VOICE_RECORDING` / `CAMERA` / `MICROPHONE`). Без согласия функция недоступна, а не просто скрыта.
3. Родитель по умолчанию **не** слушает записи голоса ребёнка. Доступ к записям пишется в аудит.
4. Файлы (аудио, записи) — только через presigned URL с коротким сроком жизни, бакет приватный. Загрузка напрямую в хранилище, не через API.
5. Для несовершеннолетних любые новые виды данных требуют согласия родителя.
6. Контроль самостоятельной работы в MVP: только сигналы браузера (переход на другую вкладку, выход из полноэкранного режима, вставка текста, время). Камера — отдельный шаг после юридической проверки.

**Тесты и оценки**
7. Правильные ответы **никогда** не отправляются на клиент до завершения попытки. Проверка ответов только на сервере.
8. Уровень навыка хранится числом 0–100, уровень CEFR вычисляется из числа (таблица ниже). Историю хранить отдельными записями (снимками), текущее значение — в профиле.

**Код**
9. Валидация всех входных данных через DTO (class-validator). Ответы API не содержат `passwordHash` и служебных полей.
10. Операции из нескольких записей — в транзакции.
11. Секреты только в `.env`, никогда в коде и в git. `.env.example` обновлять при добавлении переменных.
12. Каждая новая функция API получает проверки в `scripts/smoke-test.sh` (или отдельные тесты), включая проверку, что чужие данные недоступны.
13. Тексты интерфейса на русском; структура должна позволять добавить казахский (не зашивать строки глубоко в логику).

## Продуктовые решения (не пересматривать без обсуждения)

**Шкала уровней** (пороги — настройка в одном файле, методист может поменять):

| Балл | 0–14 | 15–24 | 25–34 | 35–44 | 45–54 | 55–64 | 65–74 | 75–84 | 85–100 |
|---|---|---|---|---|---|---|---|---|---|
| CEFR | A1 | A1+ | A2 | A2+ | B1 | B1+ | B2 | B2+ | C1 |

- Overall = среднее пяти навыков. Сильный навык = максимальный, слабый = минимальный.
- Пересчёт навыка: `new = old × (1 − w) + result × w`; `w`: placement 1.0, контрольный тест 0.4, мини-тест урока 0.1.
- Placement test: блоки по навыкам, полуадаптивная лестница (правильно → сложнее, ошибка → проще). У каждого вопроса есть навык, уровень CEFR и сложность. Speaking в MVP оценивает куратор по рубрике (vocabulary, grammar, fluency, pronunciation, 1–5).
- План на день (без AI): приоритет — три навыка с наибольшим отставанием от цели; день = урок (или часть урока по `dailyMinutes`) + повторение слов + одно задание на самый слабый навык. Куратор может изменить план.
- Контент упражнений хранится в JSONB, чтобы новые типы упражнений не требовали миграций.
- Интервальное повторение: поля SM-2 закладываются сразу, интерфейс — второй этап.
- Уведомления: модули публикуют события (`lesson.completed`, `review.created`, `assignment.overdue`...), модуль уведомлений ставит отправку в очередь с учётом настроек пользователя.

## Web (`apps/web`)

- Стиль берётся из лендинга `site/index.html`: цвета `#F4F1EA` (фон), `#16181D` (текст), `#2B3FD6` (акцент), `#D9F36A` (второй акцент), шрифты Unbounded (заголовки) и Onest (текст).
- Refresh-токен **не хранить** в localStorage. Схема: route handlers Next.js (`/api/auth/*`) обращаются к API и кладут токены в httpOnly cookies; серверные компоненты и прокси-запросы берут токен из cookie.
- Каждый кабинет — отдельная зона маршрутов: `/student`, `/parent`, `/curator`, `/admin`; middleware не пускает в чужую зону.
- Адаптивность до 375 px, видимый фокус клавиатуры, подписи у полей форм.
