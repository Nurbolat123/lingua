# Проверка платформы на своём компьютере

Инструкция для того, чтобы запустить SoyleUp у себя на компьютере (не на
сервере) и пройти все функции — как ученик, родитель, куратор и админ —
прежде чем арендовать сервер (см. `DEPLOY.md`).

Один раз всё установить и настроить — минут 30–40. Дальше запускать —
2 команды и 30 секунд.

---

## Часть 1. Что установить (один раз)

1. **Git** — скачивает код проекта.
   - Mac: откройте Терминал и введите `git --version` — если не установлен,
     macOS сама предложит установить.
   - Windows: скачайте с [git-scm.com](https://git-scm.com) (при установке
     все вопросы можно оставить по умолчанию — просто «Next»). После
     установки появится программа **Git Bash** — команды ниже вводите в ней.

2. **Docker Desktop** — поднимает базу данных, очередь и хранилище файлов
   одной командой. Скачайте с [docker.com/products/docker-desktop](https://www.docker.com/products/docker-desktop/),
   установите, запустите — иконка кита должна появиться в трее/строке меню
   и оставаться запущенной, пока вы тестируете платформу.

3. **Node.js** — версия 22 или новее. Скачайте LTS-версию с
   [nodejs.org](https://nodejs.org). Проверить после установки:
   ```bash
   node --version
   ```

## Часть 2. Скачать проект

В Терминале (Mac) или Git Bash (Windows):

```bash
git clone https://github.com/Nurbolat123/soyleup.git
cd soyleup
```

## Часть 3. Поднять базу данных, очередь и хранилище файлов

Docker Desktop должен быть запущен (иконка кита в трее). Затем:

```bash
docker compose up -d postgres redis minio
```

Проверить, что всё поднялось:

```bash
docker compose ps
```

Все три сервиса должны быть `Up` (у postgres и minio — ещё и `healthy`).

## Часть 4. Настроить и запустить API

```bash
cd apps/api
cp .env.example .env
```

Откройте появившийся файл `apps/api/.env` любым текстовым редактором
(Блокнот, VS Code) и поменяйте две строки:
- `JWT_ACCESS_SECRET=` — впишите любую случайную строку от 32 символов
  (например, просто настучите что-то длинное по клавиатуре)
- `SEED_ADMIN_PASSWORD=` — пароль для входа в админку, минимум 12 символов

Сохраните файл и вернитесь в терминал:

```bash
npm install
npm run db:migrate      # создаёт таблицы в базе
npm run db:seed         # создаёт администратора (email — из SEED_ADMIN_EMAIL в .env)
npm run db:seed:demo    # наполняет демо-контентом: курс, уроки, словарь, банк вопросов
npm run dev
```

Оставьте это окно терминала открытым — в нём работает API
(`http://localhost:3001/api/v1`, документация — `http://localhost:3001/api/docs`).

## Часть 5. Настроить и запустить сайт

Откройте **новое** окно терминала (первое должно остаться открытым — там
работает API), перейдите в проект и запустите сайт:

```bash
cd soyleup/apps/web
npm install
npm run dev
```

Откройте в браузере: **http://localhost:3000**

## Часть 6. Как проверить все функции

Заведите несколько тестовых аккаунтов — проще всего в **разных окнах
браузера в режиме инкогнито** (чтобы не путать, под кем вы вошли: сессии
хранятся в cookie браузера).

### 1. Пройти тест на уровень как гость (до регистрации)

Откройте `http://localhost:3000/test` → «Начать тест». Это как раз то, что
увидит настоящий пришедший на сайт человек — регистрация не нужна, пока
не дойдёте до конца.

### 2. Зарегистрировать родителя и ребёнка — чтобы проверить вообще все
функции, включая запись голоса

Согласия на запись голоса/камеру/микрофон в интерфейсе сейчас может
выдавать только родитель для несовершеннолетнего ученика (у взрослого
ученика такой кнопки в интерфейсе пока нет — see note ниже). Поэтому для
полной проверки удобнее пройти путь «родитель + ребёнок»:

1. **Окно 1 (инкогнито):** `/register` → «Я родитель» → зарегистрируйтесь
   (пароль от 8 символов).
2. **Окно 2 (другое инкогнито):** `/register` → «Я ученик», дату рождения
   укажите так, чтобы возраст был меньше 18 лет. После регистрации ученик
   увидит статус «ждёт согласия родителя» и код для привязки (виджет на
   `/student`) — скопируйте этот код.
3. **Вернитесь в окно 1 (родитель):** на `/parent` есть форма «Привязать
   ребёнка» — вставьте код. Появится карточка ребёнка со списком согласий:
   включите «Обработка персональных данных» (это активирует аккаунт
   ученика), «Запись голоса», «Камера», «Микрофон».
4. **Окно 2 (ученик):** обновите страницу — аккаунт уже активен, доступен
   `/student` с планом на день.

### 3. Пройти обучение как ученик

- `/student` — план на день, слова на повторение
- Открыть урок → пройти блоки, мини-тест в конце блока
- Устная часть (Speaking) — теперь доступна запись голоса (согласие дано на
  шаге выше); браузер спросит разрешение на микрофон
- `/student/homework` — сдать домашнее задание (текст и/или голос)
- `/student/vocabulary` — повторение слов

### 4. Создать куратора и проверить проверку заданий

1. **Окно 3 (инкогнито):** войдите на `/login` под администратором
   (`SEED_ADMIN_EMAIL` / `SEED_ADMIN_PASSWORD` из `apps/api/.env`).
2. На `/admin` в форме «Создать куратора или администратора» создайте
   куратора (email + пароль от 12 символов).
3. Там же в общем списке пользователей найдите вашего тестового ученика и
   назначьте ему только что созданного куратора («Назначить»).
4. **Окно 4 (инкогнито):** войдите под куратором → `/curator` — очередь на
   проверку, список учеников, фильтры («есть непроверенное», «низкий
   балл»...). Откройте ученика → проверьте домашнее задание или устный
   ответ (рубрика: словарный запас, грамматика, беглость, произношение).

### 5. Отчёт родителю и уведомления

- **Окно 1 (родитель):** зайдите на карточку ребёнка → «Прогресс и отчёты»
  — отчёт по уроку, недельная сводка.
- `/notifications` (в любом из аккаунтов) — лента уведомлений о проверенных
  заданиях, новых ДЗ и т.д. Присылаются они и на email/Telegram, если
  настроены `SMTP_*` / `TELEGRAM_BOT_TOKEN` в `apps/api/.env` — без них
  уведомления видны только в самой платформе, это нормально для локальной
  проверки.

### 6. Админка контента

На `/admin/content` под администратором — курсы, модули, уроки, словарь,
банк вопросов теста. Демо-контент туда уже загружен командой
`db:seed:demo` — можно посмотреть его устройство и добавить/отредактировать
своё.

## Известное ограничение (заметил по пути)

У **взрослого** ученика (который сам себе регистрируется, без родителя) в
интерфейсе пока нет кнопки дать себе согласие на запись голоса/камеру —
такая кнопка есть только у родителя для ребёнка. API это уже умеет
(`POST /users/consents`), просто на сайте кнопку ещё не сделали. Если
понадобится — скажите, добавлю отдельным шагом. Для локальной проверки это
не мешает: путь «родитель + ребёнок» выше проверяет то же самое.

## Если что-то не запускается

- `docker compose ps` показывает не `Up`/`healthy` → откройте Docker
  Desktop, убедитесь что он запущен, попробуйте `docker compose up -d postgres redis minio` ещё раз.
- API ругается на `JWT_ACCESS_SECRET must be at least 32 chars` → в
  `apps/api/.env` строка короче 32 символов, допишите.
- Сайт открывается, но везде ошибки при загрузке данных → проверьте, что
  окно с `npm run dev` в `apps/api` всё ещё открыто и без ошибок.
- Хотите начать заново с чистой базой:
  ```bash
  docker compose down -v   # удаляет данные Postgres/Redis/MinIO
  docker compose up -d postgres redis minio
  cd apps/api && npm run db:migrate && npm run db:seed && npm run db:seed:demo
  ```
